# 英语作文批改规则

> 适用范围：高中英语 **Guided Writing**（不分体裁、不设题面范围）的批改与升格，产出一份 Word 批改稿。
>
> **本文件只管批改，不适用于讲义生成。** 讲义里的写作大题按 `规范/01-讲义制作规则.md` §2.9 走（保留原题要求 → 高分参考范文 → 写作架构与亮点表达赏析），
> 与本文的红标需改处、蓝色编号、五部分结构、参考翻译**毫无关系**。做讲义时**不要打开本文件**，哪怕只是想"核对版式"；
> 做批改时也不要顺手翻 01。规则路由见 `HANDOVER.md` §0.7。

---

## 0. 一句话总则

**把学生原文完整转录 → 按行文顺序给出"纠错＋补充意见" → 给一篇与意见逐条对应的唯一终稿 → 附一段纯中文参考翻译；红色标原文需改处，蓝色标终稿对应编号；【特别重要】：不空行、所有中文必须宋体（**圈号 ①②③ 和全角标点也算中文，不许掉进 Times New Roman**）！所有英文必须Times New Roman、页面设置为 A4。**

## 1. 输入与输出

| 项 | 约定 |
|---|---|
| 输入一 | **作文题目**：含英文 Directions 与中文指令（含"内容须包括"的要点）。**格式不限**——doc / docx / pdf / 各类图片 / 可读出内容的链接，只要其中含题面文字即可 |
| 输入二 | **学生作文**：**格式不限**。可能是**纯文本电子稿**（doc / docx / pdf / 图片 / 链接），也可能是**手写照片**（单页或分两页拍）—— 后者先按 §7 做 OCR 转录再批改，**错误照录**，不做任何修正 |
| 输出 | 一份 `.docx`，由脚本用 `doc.save()` 保存到工作区的 `生成物/` 子目录 |
| 数量 | **输入侧不限**：单次最多 25 个文件，格式可混用；**输出侧仍是一次一篇，绝不合并**多篇成一份 |
| 体裁 | **任何 Guided Writing 都接**（书信、投稿、征文、演讲稿、通知……），不预设体裁 |
| 题面来源 | 题面一律以上传的题目文件为准，**不得套用规则或模板里的任何示例题**；题目文件缺题面时按 §2 处理 |

**关于格式与插图（本节通则，三套体系通用）**：

- 接收任何**模型能辨认**的格式：`doc` / `docx` / `pdf` / `png` `jpg` `jpeg` `heic` `webp` 等图片 / 能抓到正文的网页链接。判断标准只有一条——**能不能从中读出文字**。
- **输出形式要先问**：输入明显可能导致成品超过单篇时（如一次给了三五篇作文），**必须先问用户是每篇各出一份、还是合成一份**，不得自行决定。
- 原件含插图（图表、示意图、漫画等）时，**尽量把图裁出来插进成品、放回原文对应位置**，不要把插图写成"此处原为插图"的文字描述。
- **三套体系的插图默认值不同**，不要混用：**试卷识别**默认保留图文、无需询问；**讲义生成**默认移除插图，且动手前必须先问一句；**作文批改**（本体系）默认保留，作文题面里的图表本来就不多，按「能裁就裁」处理即可。
- **不要求 100% 还原位置**，尤其是文字环绕、跨栏排版这类，做不到也不必强求；能对上段落顺序即可。
- 插图**特别不清晰**（糊、暗、被遮挡、分辨率过低）时，照常按最可能的读法处理，但**必须在交付文字里点一句**，让用户知道这处不可靠。

## 2. 文档结构（固定五部分 + 大标题 + 副标题）

| 顺序 | 部分 | 要点 |
|---|---|---|
| — | **大标题** | 14pt 加粗居中：`高三英语写作训练《××》批改与升格（终稿版）`，`××` 填作文话题，不是题目原文 |
| — | **副标题** | 9pt 斜体居中：`〔体裁〕；黑色原文＋红色＝需改处；小号蓝色〔〕＝终稿与意见的对应编号；未标注的句子为原文保留句`。开头那个体裁词**按实际填写**（书信（电子邮件）／投稿／演讲稿／通知……），不要照抄模板里的「书信（电子邮件）」 |
| 一 | **作文要求** | 题面原文转录，一字不改。**题面缺失时不编造**，只标 `同题：××` |
| 二 | **学生作文（原文完整转录，保留原有语言表达与错误）** | 完整文章，**保留原有表达与错误**；下方 9pt 斜体注明词数与缺件情况 |
| 三 | **修改意见（纠错 ＋ 补充意见）** | 分两块：**（一）纠错**　**（二）补充意见** |
| 四 | **终稿** | **唯一版本**，不分"基础版／高分版"；每句后带蓝色〔〕编号 |
| 五 | **参考翻译** | 终稿的**纯中文**译文；**不加任何〔〕标记、不加批注意见**；不必逐句对应，按段落意译，力求信达雅 |

说明：

- （一）纠正语言错误，并把不地道、过重、搭配不当的表达换成更自然、更凝练的英语。
- （二）原文没有错、但补上能更充实更贴题的"凭空加一句"，必须写明**位置**和**增加内容**。
- **参考翻译**译的是**终稿**，不是原文；目的只有一个：让学生知道改完之后到底在说什么。所以宁顺不顺字，允许合并句子、调整语序，**但不得增删终稿没有的意思**。

**什么算「错」、什么不算（这条最容易被放宽，务必守住）**：

- **算错**：语法（时态、主谓一致、冠词、单复数、词性、句子成分）、拼写、固定搭配、指代不清、中文直译。
- **不算错**：**缩写**（`I'm`／`couldn't`／`Let's`／`don't`／`it's`）—— 演讲稿、书信、日记里都是正常语域，
  **一律不标红、不单独立纠错条**；口语化但不违反语法的表达；学生自己选的句式。
- **判据**：把原句读给英语母语者听，**会不会被当成错误**。只是"可以更高级／更正式"的，不算错 ——
  这类内容要么放进补充意见，要么**干脆不动**。
- **纠错的条数不是指标**。为了凑条数去改没毛病的句子，是这份批改稿最严重的失误 ——
  学生照着改，反而把对的改成别扭的。

## 3. 排版规范（数值照抄，勿自创）

| 项 | 值 |
|---|---|
| 纸张 | **A4**，21.0 × 29.7 cm |
| 页边距 | 上下 **2.0 cm**，左右 **2.2 cm**；页眉页脚距 1.27 cm |
| 中文字体 | **宋体**（必须设 `w:eastAsia`，只设 `font.name` 不生效） |
| 英文字体 | **Times New Roman**（`w:ascii` / `w:hAnsi` / `w:cs` 全设） |
| 中文符号 | 圈号 **①②③**、全角标点（，。：；！？（）「」《》、——……）、全角空格 **一律算中文，用宋体**；必须靠 `w:hint="eastAsia"` 保证，否则会掉进 Times New Roman（见 §3.1） |
| 正文 | 10.5 pt，行距 1.15，段前段后 **0**，首行缩进 **12 pt** |
| 大标题 | 14 pt 加粗居中，段前 0、段后 0 |
| 副标题 | 9 pt 斜体居中，**段前 2 pt、段后 4 pt** |
| 章节标题（一 ~ 五） | 12 pt 加粗，**段前 8 pt、段后 0** |
| 二级标题（（一）（二）） | 11 pt 加粗，**段前 6 pt、段后 0** |
| 说明性小字 | 9 pt 斜体（词数行、副标题、纠错/补充的分类说明行、文末提示行） |
| 红色 | `#FF0000` ＝ 原文需要修改的地方 |
| 蓝色 | `#1F4E79`、8.5 pt 的〔〕＝ 终稿与意见的对应编号 |
| 空行 | **正文段落之间不空行**；只在 **5 处**各留一个空段落：四个章节交界（一｜二、二｜三、三｜四、四｜五）＋ **（一）纠错｜（二）补充意见 之间** |
| 对齐 | 正文两端对齐；**题面里的英文行（`Guided Writing`、`Directions: …`）顶格不缩进**，中文题面缩进 12 pt；`Yours sincerely,` 与署名右对齐且**不带首行缩进** |

排版是成品的硬指标：字体、字号、颜色、缩进、空行必须全部落实，不留"差不多"。

### 3.1 圈号和全角标点必须算中文（最容易踩的坑）

批改说明里的分点写 ①②③，正文里还有全角括号、全角冒号、全角逗号、全角空格。这些字符看着像中文，
**但 Word 默认会把它们当西文排成 Times New Roman** —— 圈号变成罗马体的瘦圈、全角括号变成半角形状，
和旁边的宋体字明显不是一个体系。

原因：Word 判定一个字用哪套字体，看的是 `w:rFonts` 里的三个槽（`w:ascii` / `w:hAnsi` / `w:eastAsia`）
**再加一个 `w:hint`**。①②③、全角标点、全角空格都属于"东亚歧义宽度"字符：
**`w:hint` 不写 `eastAsia` 时，Word 会退回 `w:ascii`**，于是它们走了 Times New Roman。

所以每个 run 的 `w:rFonts` 必须写全，一个都不能漏：

```python
run.font.name = 'Times New Roman'          # 只写 w:ascii / w:hAnsi，管不到圈号
rPr = run._element.get_or_add_rPr()
rFonts = rPr.get_or_add_rFonts()
rFonts.set(qn('w:eastAsia'), '宋体')
rFonts.set(qn('w:hint'), 'eastAsia')       # ← 少了这一行，①②③ 和全角标点就变西文
```

`w:hint` 只对"歧义字符"生效：英文字母仍然走 `w:ascii`（Times New Roman），不会被改成宋体。
**所以不必按字符切 run，整段统一设成上面这样即可。**

**验收方法**：把成品 docx 解压，`word/document.xml` 里每一个 `<w:rFonts` 都应该同时带
`w:eastAsia="宋体"` 和 `w:hint="eastAsia"`；缺一个就说明有字符会跑成西文。

**空段落和段前距是两件事，不能互相替代。** 章节标题前面那个空段落只负责"隔开"，不负责"留白"；
五个章节标题**每一个都要段前 8 pt**，不许因为"前面已经空了一行"就把段前设成 0。
（实测踩过：五个标题里只有第一个是 8 pt，后四个被设成 0 pt，肉眼几乎看不出来。）

## 4. 批注的写法

1. 每条批注**重新列一遍原文**（黑色），**红色只标真正需要改的片段**，不要整句标红。
2. 紧跟 `　→　修改为：……　说明：……`（全角空格分隔）。
3. **必须给出理由**，不能凭空下判断；说明分点写 ①②③。
4. 一条意见解决一类问题；同一句的多处问题可合并在一条内说明。
5. 编号 `纠1、纠2……` / `意1、意2……`，**严格按文章读取顺序**，不允许跳读、不允许乱序。
6. **删除项**要写明"整句删去"，并注明"**终稿中无对应文字**"。
7. 每条前面加一个短标签概括问题，如 `纠2·第二段：AI 翻译的局限（语法硬伤）`。

### 4.1 范例（照这三条写，笔调就对了）

> 以下三条是标准笔调，**格式与口吻照此仿写**。

**范例一 · 语法硬伤，逐点诊断**

> 纠2·自我介绍　I'm your student Wangjia from grade 12.　→　修改为：I'm Wang Jia, a Senior 3 student of yours.　说明："王佳"的规范拼写是 Wang Jia，姓与名分写、首字母都大写，全文（含落款）要统一；grade 12 是美式说法，上海高中写作通常用 Senior 3；"your student Wangjia"作同位语有点生硬。

**范例二 · 拼写＋冗余＋语域＋结构，一条打包**

> 纠6·拼写与用词　Mastering precise information retrieval techniques in this course will help me cut through masses of irrelevant resourses, which will greatly boost my efficiency when looking up academic materials for my College application essays.　→　修改为：Mastering precise retrieval techniques will help me filter out irrelevant resources and find academic materials for my college application essays far more efficiently.　说明：resourses 拼写错误，应为 resources（卷面已圈出）；in this course 冗余，全文都在谈这门课；cut through masses of 偏口语，书面语可用 filter out / sift through；which 从句＋when looking up 双重结构拖沓；College 在句中不大写。

**范例三 · 删除项，要给替代方案**

> 纠9·课程名用法与语义重复（删除项）　Therefore, learning the course of "Discerning Authenticity of Information" can be of great help in avoiding being cheated by fake information.　→　修改为：整句删去，"避免被误导"这层意思并入纠8 那一句。　说明：the course of＋课程名不规范；can be of great help in avoiding being cheated by 冗长且偏口语；且与上一句语义重复。若坚持保留，可写：Taking this module will help me distinguish reliable information from fake news.（终稿中无对应文字，属删除项。）

**三条范例的共同点（照做）**：

1. 先**重列原文全句**，红色只标真正要改的片段，其余保持黑色；
2. 说明用**分号连缀**，一条一条点名具体问题，**不写"应改为更地道的表达"这种空话**；
3. 会**引用卷面痕迹**（"卷面已圈出""与卷面批注一致"），证明真的看过原稿；
4. 删除项**必须给替代方案**，不能只说"删掉"；
5. 一条批注可以打包同句多处问题，但**每一处都要归类**（拼写／冗余／语域／结构）。

### 4.2 升格幅度（改到什么程度算合适）

| 动作 | 对象 |
|---|---|
| **该删** | 万能套话：`After careful consideration`、`In today's globalized world`、`Last but not least`、`In conclusion`＋`I strongly believe` 叠加、`here is why`、`As we all know` |
| **该换** | 中式直译、生造词、搭配错误、**明显**语域不合场景（把 `gonna` 写进正式投稿、把论文腔写进给笔友的信）；同义堆叠（`rewards and gifts`）。**缩写不算语域问题** |
| **该留** | 学生自己的例子、观点、段落顺序、个人化细节、有灵气的句子（哪怕有小错，改错不改句）；语法正确的口语化表达 |
| **不该做** | 把学生的话整段重写成自己的话；把观点换成"更高级"的观点；为了升格而加学生想不到的内容；**把语法正确的句子按"更正式"改掉**（`Let's`→`Let us`、`I'm`→`I am`、`couldn't`→`could not` 都属此类） |

**判断标准**：改完之后，**读起来仍像这个学生写的，只是英语更好**。如果读起来像另一个人代笔，就是改过头了。

## 5. 终稿与意见的双向对应（硬要求）

- **每条意见在终稿里必须有落点**；**终稿每一句都必须来自某条意见**（原文保留句除外，且保留句不加标注）。
- 不允许"提了意见没改"，也不允许"改了却没在意见里说过"。
- 多条意见共同指向一句时，写〔纠4、纠8〕。
- **删除项**：在**被删内容所在的段落开头**打〔纠N〕（表示"此处有删减"），并在终稿上方那行说明里注明"纠N 为删除项"。不要用省略号或空白代替。
- **全篇性问题**（段落过少、通篇缺落款之类）：没有单句落点，只在说明行注明"纠N 为全篇性意见，无单句落点"，**不参与下面的核对**。
- **保存前必须核对**：意见编号集合 ↔ 终稿标注集合，两者必须完全相等（全篇性问题除外）。
  出现"有意见无落点"或"有标注无条目"，一律视为不合格，必须修好再保存。

## 6. 字数规则（务必遵守）

**忽略题面标注的词数限制**（题面没标词数、或标的是别的区间，一律照下表执行），改用下列口径：

| 原文词数 | 终稿词数 |
|---|---|
| 明显偏少（< 220） | **补到 220 词左右**（可到 230，靠补充意见加料） |
| 220 ~ 260 | **保持原文词数**，不必压 |
| 远超（> 260） | 先挑**明显废话／重复／无意义句**删一点，再补建议内容，仍落在**原文词数附近**（±15） |

补充：

- 浮动 **±15 词**属正常，不必精确到个位。
- **不设"全篇超词"这条纠错**；原文词数只写在"学生作文"下方，**不做超限评判**。
- 原文词数照实统计；缺落款、缺结束语等缺件要在同一行注明。
- 因不压字数，补充意见可以是**净增**（加句、加例证），不必强求"替换式"。

## 7. 转录规则

- **两种来源都要接**：① 纯文本电子稿 —— 直接读，不改一个字；② **插在 docx 里的手写照片**（拍完照插进 Word，正文没有文字）—— 先看图 OCR 成完整文章，再批改。照片有折痕、光线不匀、字迹潦草时，按上下文取最可能的一种读法，**不编造、不留 `[?]` 占位**。
- 手写体 → 完整文章，**错误照录**（拼写错误如 `resourses`、`boarder` 也保留），留在批注里指出。
- **忽略卷面批改痕迹**：老师的红笔、圈画、标号、分数、题目上的批注，一律不计入转录。
- 转录完在文末提示行**注明本稿来源**：`本稿由电子稿转录` 或 `本稿由手写照片转录`。

### 7.1 OCR／录入错误的处理

**核心原则：先怀疑录入，再怀疑学生。** 老师看手写稿时，一个像竖线的字母自然读作 I，不会判错；批改者也该这样读。

| 情形 | 处理方式 |
|---|---|
| **不作为纠错项** | 明显是 OCR 或录入造成的错误（`Al`/`AI`、`O`/`0`、`l`/`1`、`rn`/`m`、标点后缺空格、逗号前多空格、`---` 当破折号），**不进意见**；但**必须在文末列清单**，说明自动纠正了哪些（见 7.2） |
| **底线** | **终稿本身必须格式正确**：原稿 `Al` → 终稿写 `AI`；标点后该加的空格照加；破折号用 —。**"不纠"不等于"照抄错"** —— 不写进意见，但成品必须是对的 |

### 7.2 文末 OCR 清单

文末用 9pt 斜体写一行，**要点名具体错在哪**，不能只说"有个别识别误差"：

> （提示：本稿由电子稿转录。已自动纠正的识别错误：① 原稿 `Al` 应为 `AI`，终稿按 `AI` 处理；② 原稿句号、逗号后普遍缺空格，终稿已按英文规范补齐。以上均不计为批改意见。）

- 逐条列，**每条写清"原稿是什么 → 终稿怎么处理"**
- 结尾固定一句"以上均不计为批改意见"，划清界限
- **没有识别错误时，只写来源那一句**（如"（提示：本稿由电子稿转录，未发现需要说明的识别错误。）"），**不要编造条目**凑数

## 8. 内容与语言要求

- 依据**作文题目要求 + 上海高考难度**出意见。
- 方向是**适当提升语言层次、丰富语言表达、用更地道的英语**。
- **扣题优先**：例子和细节不能离题；举例要就地取材，紧贴来信人的处境（教训：学生想做饭，却举"学艺术建作品集、找工作找实习"的例子）。
- 应试硬指标要盯住：
  - "须包括"的要点是否**逐条答到**；
  - **署名是否与题目人物一致**（题设 Li Hua，就不能写成 Li Ming 或收信人名字）；
  - **体裁格式是否完整**（缺一即为硬伤）：书信要"称呼、正文、结束语、署名"四件套；演讲稿要有称呼与结尾致谢；投稿要有标题；通知要有对象与时间地点；
  - 书信的结束语 `Yours sincerely,` 后必须加逗号；
  - 称呼规范（英语无 `Dear Teacher Lucy` 这种"Teacher＋名"的说法）。

### 8.1 高频语言点处理惯例（28 篇沉淀，逐条照办）

| 现象 | 处理方式 |
|---|---|
| 缺称呼／缺结束语／缺署名 | **各立一条纠错**，标签写"（整段缺失）"，终稿补齐；不要合并成一条 |
| 段末缺句号 | 单独立一条，说明里点明"卷面硬伤"，终稿只补标点、不动句子 |
| 主谓不一致（动名词／复数主语配单数谓语） | 一条纠错，必须点出"主语是什么、谓语该用什么" |
| 逗号粘连（两个独立句用逗号连接） | 一条纠错，给出分号、连词两种改法 |
| 政治口号、宏大叙事（"人类命运共同体"等） | 判为**离题**，作删除项处理，说明里讲清"语域不对＋不是理由" |
| 论点与事实相反（如"AI 译得准但慢"） | **必须重写论点**，不是改词；说明里要指出"与常识相悖，阅卷人一看就不成立" |
| 两段内容重复 | 合并为一段，说明里**逐条列出重复的原句**，并点明"凑字数" |
| 笔记残留（正文里的括号提示） | 删除，说明里点明"会被判为未完成稿" |
| 生造词（`delication`、`unknowledge`） | 一条纠错，写明"英语里没有这个词"，并给正确词与搭配 |
| 语义说反（`be outshined`、`won't take you too far away`） | 一条纠错，指出"意思正好相反"，属最严重的一类 |
| 署名拼写 | 一律 `Li Hua`（姓与名分写、首字母大写），**署名后不加句号** |
| 段落过少／过挤 | 一条**结构类**纠错，说明"一段一条理由"，并指出该拆该并 |
| 标点后缺空格／逗号前多空格／`---` 当破折号 | **不纠**（手写转电子版的产物，见 §7）。终稿按正常排版输出即可，但**不要在意见里提**，否则是冤枉学生 |
| `Al`/`AI`、`O`/`0`、`l`/`1`、`rn`/`m` 等形近字符 | **不纠**（OCR 产物）。按上下文理解即可；同一文档反复出现时，**文末提示一次**，不进意见 |
| 连字符、大小写、引号样式的前后不一致 | 先判断是否录入造成：可能是手写原样，则纠；纯属录入，则不纠 |

### 8.2 用词与格式统一口径（全篇一致，不许一会儿一样）

| 学生常写 | 统一处理 |
|---|---|
| `thrilled` | → `delighted`（thrilled 意为"极其兴奋"，朋友说想学语言用词过重） |
| `a lot of` / `lots of` | → 具体量词（`a wealth of`、`plenty of`）或直接删 |
| `very important` | → `essential` / `crucial` |
| `can not` | → `cannot`（一个词） |
| 正文里的 `it's` / `don't` / `can't` | → `it is` / `do not` / `cannot`（书面书信不用口语缩写；**对话式引用可保留**） |
| 英式／美式拼写 | **全篇统一**，不许混用（`memorise`／`organise` 与 `memorize`／`organize` 择一） |
| 汉语拼音 | **不标声调**（写 `da dian`，不写 `dǎ diàn`） |
| 数字 | 正文用拼写（`five thousand`），不用 `5000`；作定语时用连字符（`a 5,000-year history`） |
| 标点 | 英文正文一律**半角**；全角只用于中文题面与批注里的中文说明 |
| 引号 | 英文正文用直引号或弯引号须全篇统一，中文说明用「」或"" |

## 11. 附：进一步升格版（条件触发）

> **这一节只在触发时才用。没触发就别读、也别做**——默认流程只出批改稿一份。
> 这一节不进技能包的路由表，因为它不是默认产物。

**触发**（两条同时满足）：

1. 材料命中本规范（作文批改）；
2. 提示词里有「进一步升格／再次升级／再次升格／再出一版更高的」一类意思，分两次对话说也算。

**最简判据：只有文字、没给新材料。** 上一份批改稿刚交付，这一条消息不带新作文、只提要求，
基本就是这类请求。给了新作文就是新任务，走默认流程。

**做不做**：

- **5 秒以内**进来的请求，先问一句是不是真实意愿（可能是排队机制把一句话拆成了两条）。
- **超过 5 秒**，视为正常表达，直接做，不必纠结。
- **只对当篇有效**：下一篇（题目相同、内容不同也算新）回到默认流程，当上一版没发生过。
- 用户说「后面几篇都这样」「今天所有作文都这样」→ 按他说的批量做。
- 用户说「以后的作文都这样」→ 等于改默认流程，**提示需要口令**，没口令不动手。

**版式**：

| 项 | 值 |
|---|---|
| 结构 | 大标题（14pt 加粗居中）／副标题（9pt 斜体居中）／「一、升格版」／「二、表达对照（改了什么、为什么这么改）」／文末 9pt 斜体提示行 |
| 对照表 | 三列 **1:1:2**（4.15 / 4.15 / 8.3 cm）；表头加粗，正文 9pt；一、二列左对齐，第三列两端对齐 |
| 表宽 | **撑满正文宽 16.6 cm**（A4 21 − 左右边距 2.2×2）。`tblW` 用 twips = **cm × 567**，`tblInd` 显式写 **0**；写错表会只剩一半宽、假换行、纵向拉长（见 `技术要点.md` §八） |
| 字体 | 与正文同口径：中文宋体、英文 Times New Roman，四槽写全（见 §3.1） |
| 内容 | **只换语言，不动内容**：观点、结构、理由、例子、结论全部不变。词数可与终稿相当或略少——句子变紧，不是删内容 |
| 第三列 | 写「为什么更高级」，一条一句，点出替换的具体理由，不写"更地道、更高级"这种空话 |

**分寸**：改完读起来仍像这个学生写的，只是英语更好；整段像换了一个人，就是改过头了。

### 11.1 计数与固化提议（别漏了这一步）

「进一步升格」目前是**条件产物**，每次都要单独提。用户连续提了几次，说明它可能就是常态——
所以要数着，够数就问一句要不要固化。

**计数器**：`原料/状态/升格计数.md`，一行数字，一次「进一步升格」请求 +1（一篇算一次，批量请求按篇数算）。
不建在仓库根（目录卫生），不进版本库（是本机状态）。

**触发点**：

| 累计次数 | 动作 |
|---|---|
| 1～2 | 不提，正常做完 |
| **3（含）** | 在生成物和必要说明的**最后**，附一段「要不要固化」的提问（见下） |
| 3 次时用户说「不要」 | **计数清零，阈值改为 5**——下次累计到 5 才再问 |
| 5 次时用户又说「不要」 | **从此不再提这件事**，按老规矩一篇一篇单独做 |
| 任何一次说「要」 | 给出可复制的口令原文，等用户发口令后再改规则；**口令没到手就不改** |

**提问怎么写**（写在正文最后，一段话，不要弹窗——微信看不见弹窗）：

> 顺带一句：这已经是第 3 次让我做「进一步升格版」了。要不要把它固化成永久规则——
> 以后每篇作文批改都自动附一份升格版，不用每次再提？
> 要的话，把下面这一行直接发我：
>
> 修改规则：把「进一步升格版」固化为默认流程，以后每篇批改稿都同时附升格版。
>
> 不要就回一句「不用」，我把计数清零，下次累计到 5 次再问。

**注意**：

- 提问只在**次数到位**时出现，其余时候一个字都不提，别每次都问。
- 用户说「要」之后，先给口令原文，**等他真的把口令发过来**再动规则；他没发就继续按条件产物做。
- 用户明确说过「以后都这样」——那是当场授权，走 §11 的例外分支（提示要口令），不靠计数器。
