【技能打包提示词】
使用方法：哪天要打包技能，把下面「=== 提示词开始 ===」到「=== 提示词结束 ===」之间的内容整段复制发给我即可。
不用管当时仓库到哪个版本、有没有未提交的改动，提示词里已经写了让它现场探测。

=== 提示词开始 ===

请把我们这套高三英语教学规则打包成一个可独立分发的技能包（Skill）。

下面每一条都是判据，不是建议。凡是与仓库现状有关的信息（版本号、日期、文件路径、有没有未提交改动），
一律现场探测，不要凭记忆或假设；我写的路径如果跟仓库现状不一致（改过名、挪过位置），以仓库现状为准。

一、先探测现状，不要问我版本号
1. 在工作区根目录跑 git log --oneline -5、git tag --sort=-v:refname | head -3、git status --short，
   拿到三件事：最新 tag 是哪个、HEAD 有没有领先远端、工作区有没有未提交改动。
2. 工作区干净且 HEAD 上有 tag → 副本标注「导出自 <tag>，<YYYY-MM-DD>」。
3. 有未提交改动 → 先问我一句「要不要先 commit 并升版再导出？」。
   我若说不用，就照工作区现状导出，副本标注「含未提交改动，不对应任何 tag」，
   并把这批改动涉及的文件名列出来。
4. 版本号和日期一律用命令结果，不许用记忆里的。

二、只装这五类，别多装
1. 规则：规范/ 下全部 md（01 讲义、02 批改、03 试卷识别、03 学生手写转录、04 链接下载）。
2. 版式参照：模板/01-标准模式讲义.docx、模板/02-标准模式批改.docx、示例/02-示例-批改稿.docx。
3. 可执行件：工具/check.py、工具/strip_watermark.py、工具/xhs_grab.mjs、
   jiangyi/jy_builder.py、jiangyi/practice_style.py。
4. 硬知识：从 技术要点.md 里裁三节——字体四槽、Word XML 元素顺序、表格固定布局（含 tblW / tblGrid 写法），
   其余不要。这三节是「不这么写就打不开、字体全变」的硬知识，不是历史，必须带。
5. 特殊指令：把 AGENTS.md 的硬规则、HANDOVER.md 的目录约定、规则路由表，压成一段「硬规矩」，
   写进 SKILL.md 开头。

三、明确不带（历史与导航，对上手没用，只占上下文）
- 变更日志.md（纯版本史）
- 索引.md（技能本身就是导航）
- HANDOVER.md 的待办表、版本史、长案例（只取硬规矩与目录约定）
- README.md
- 生成物/ 与 原料/ 里的任何东西
- build/ 下绑定单份试卷的生成脚本（build_jdfz.py、gen_jy.py 之类）

四、SKILL.md 正文控制在 150 行以内
1. 开头 5 行：这是干什么的、什么时候触发。触发词照抄——生成讲义、批改作文、识别试卷、
   图片转 Word、手写转录、发来一条链接。
2. 「一个任务只读一份规范」路由表，照抄，并写明两条：讲义绝不打开 02；
   找不到规定就是没有规定，按模板形式 + 常规做法处理，不许去隔壁体系翻。
3. 硬规矩四条：
   - 改规则必须用户本人连续说出「修改规则」四字；撤销 / 删除 / 回退同样要口令；
   - 成品一律写 生成物/，原料一律放 原料/<任务名>/，根目录只放规则与脚本；
   - 插图默认值三套不同：识别保留、讲义移除且事后在回复里提示、批改保留；
   - 全流程只有两处打断用户（输出可能多份、去水印吃不准），其余全自动。
4. 交付前体检命令：python3 工具/check.py <成品.docx> --kind 01|02|03。
5. 规则细节一律靠引用文件按需读，不许把上千行规则正文塞进 SKILL.md。

五、副本元信息（必须有，否则半年后没人知道对应哪版）
1. SKILL.md 顶部、以及每个被复制的规则文件第一行，各加一行：
   「本副本导出自 <tag 或「含未提交改动」>，<YYYY-MM-DD>；以仓库 tag 为准，冲突时以仓库为准。」
2. SKILL.md 里写明：包内规则是只读快照，要改规则请回仓库改、改完重新导出，
   不要在技能目录里直接改。

六、产出与自检
1. 输出到 生成物/技能包-<YYYYMMDD>/，结构按 skills 规范：SKILL.md 在根，
   规则与模板放 references/，脚本放 scripts/；最后压成同名 .zip。
2. 自检三件事，结果写进回复：
   - 包里每个文件都能打开；md 无乱码；docx 能被 python-docx 读出来
   - SKILL.md 正文行数、整个包的文件数与体积
   - 假设一个从没读过本仓库的 agent 只拿到这个包，能不能按 SKILL.md 跑通一次讲义：
     把「它会依次读哪些文件」列出来，确认没有一个路径是不存在的
3. 不许改动仓库里任何规则文件。这是导出，不是改规则。

七、最后回我一段话
版本与导出依据、装了什么（文件数 / 体积）、砍了什么、三处自检结果，
以及这个包的已知局限（比如模板 docx 只是版式参照、不含真实题目，缺真实卷子时得自己给）。

=== 提示词结束 ===
